# 磕【new】项目指令：GitHub 路标版

“磕【new】”项目的静态资料以 GitHub 仓库 `laippmiles/ke-project` 为准。主分支是 `main`。二创资料位于仓库根目录下的分类目录中，不再进入 `磕/` 子目录。

每次需要读取、写入或维护项目资料时，先打开 `00_入口与规章/磕_GitHub_入口索引.md`，再按索引进入具体文件。原 Google Drive 和 ChatGPT Library 文件只作为迁移历史背景；除非用户明确要求回查旧版，不再作为日常读取或维护位置。

长期写作规章以 `00_入口与规章/磕_项目规章_杀生丸与铃.md` 为准。涉及人物声音、称呼、关系阶段、资料调用和正式出文检查时，先读取该规章，再根据任务读取写作圣经、人物理解、对白集和对白分析。

资料读取、写入、迁移、归档和隐私边界以 `00_入口与规章/磕_资料维护规章.md` 为准。凡是与项目创作无关的个人生活、健康、用药、家庭、工作、账号、财务、联系人、现实身份信息，或被标记为私密、个人、敏感、备忘、仅自己看的材料，不进入默认读取、迁移、归档或更新范围；只有用户对具体文件或具体类别单独明示批准后，才能处理。

正式交付小说正文、场景扩写、人物对白、情节大纲、续写或成稿修改前，必须读取当前任务相关资料。默认读取 `01_核心总集/磕_谈话总集_02_二创世界观与长线创作圣经.md`；涉及杀生丸与铃的关系判断时，同时读取 `01_核心总集/磕_谈话总集_01_杀铃关系研究与人物理解.md`；涉及杀生丸对白时，同时读取主体版 `02_原作对白与校准/10_主体对白集/杀生丸前期对白_杀邪铃互动_原作对白集.md` 和 `02_原作对白与校准/20_对白分析与台词校准/杀生丸前期对白_杀邪铃互动_对白分析与二创校准.md`。

讨论过程中不要立即提交。先记录待更新内容，等待用户明确表示“敲定”“归档”“提交”“按这个改”等确认。用户确认后，再更新静态资料，并尽量把同一轮讨论敲定的结果合并为一个 commit。提交后回读 commit 或文件内容，确认变更范围符合本轮讨论。

草稿完成后，回到写作圣经的“连续性检查清单”和“正式出文自检”复查。发现冲突、人物失真、称呼错误、设定错位或模板化表达时，先修改再交付，不需要在回复中报告检查过程。

如果无法访问指定 GitHub 资料，必须明确说明缺失，不能凭记忆补设定，也不能编造原作对白。

当前迁移的是可访问的项目静态资料，不等于旧项目完整聊天逐字原文已全量迁移。不能把“已迁移资料”说成“完整历史聊天已备份”。
